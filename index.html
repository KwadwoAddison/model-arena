Method & notes

How scoring stays honest

  1. Blind. Model identity is stripped before grading. The grader sees answers, not authors.
  2. Deterministic where possible. Code tasks execute against held-out unit tests. Arithmetic tasks are checked numerically. Only prose tasks face a rubric, and the rubric text is published.
  3. Par-token efficiency. Each task carries a par token budget (median of family history). Under par earns credit; over par loses it; efficiency never rescues a wrong answer.
  4. Reasoning sweep. Every model runs at three effort levels; the site shows all three, so a cheap model can be picked deliberately for cheap jobs.
  5. Fresh models enter equal. Adding a model to roster.json is enough; the next run scores it against identical tasks and folds it into the par history. No legacy advantage, no newcomer penalty beyond sample size.
  6. Sample-size honesty. Any model with fewer than 5 graded runs in a cell shows its score with a "thin" flag instead of a rank.

Built as a living system: bench.py writes JSON, this page reads it. When you add model 8, nothing here is rebuilt. It is re-run.
